## 1. 项目概述

### 1.1 一句话定义

把孟德尔测交实验从"课本上的一段结论"变成**学生亲手跑一遍的完整实验流程**——从花蕾期去雄、逐朵套袋、蘸粉授粉、重新套袋，到花谢结荚、采收种子、播种、长成、分类计数，最后用自己数出来的 24∶24 去检验演绎推理预测的 1∶1。

核心设计立场：**这一课的重点不是背结论，而是走完假说—演绎法的第四步（实验验证）。**

### 1.2 硬约束（不可妥协）

| # | 约束 | 原因 |
|---|------|------|
| C1 | **单文件交付** | 公开课现场环境不可控（无网络、无服务器、U 盘拷贝） |
| C2 | **零外部依赖** | 不引 CDN、不引字体文件、不引图片；所有图形用内联 SVG 程序化生成 |
| C3 | **触屏优先** | 目标设备含平板 / 触控一体机；全部交互基于 Pointer Events |
| C4 | **严格对齐人教版** | 术语、流程顺序、遗传学结论必须与教材一致；见第 2 章 |
| C5 | **不替学生得结论** | 程序的职责是提供材料与工具，不是替学生观察和推理；见 2.5 |
| C6 | **零 `lint`/运行时错误** | 控制台无 error、无 uncaught exception；由回归测试守住 |

## 2. 教学依据与内容校准

### 2.1 教材定位

- **教材**：人教版 · 高中生物必修 2《遗传与进化》
- **章节**：第 1 章 遗传因子的发现 → 第 1 节 孟德尔的豌豆杂交实验（一）
- **教材原文流程**（必须严格一致）：
  1. 花蕾期**去雄**（豌豆闭花受粉，开花前已完成自花传粉，必须在花蕾期操作）
  2. **套袋**（隔离外来花粉）
  3. **取粉**（从父本成熟花药上蘸取）
  4. **授粉**（把花粉涂到母本雌蕊柱头上）
  5. **再套袋**（防止二次污染）
  6. 待种子成熟、**采收**、次年**播种**、观察后代表型

> 本产品将教材的"次年播种"压缩为同一场次的"花谢结荚 → 采收种子 → 播种"，属于**教学时间压缩**，不改变任何遗传学事实，但必须在 UI 上明确标注这一步是"时间加速"，避免学生形成"当年就能种"的错误印象。（当前通过豆荚生长动画 + 文案"子房一天天膨大"表达。）

### 2.3 假说—演绎法四步与本产品的映射

```
第一步  观察现象·提出问题   ──  引导弹窗「孟德尔假说」页交代背景（F₁ 全高茎、F₂ 3∶1）
第二步  提出假说·解释问题   ──  弹窗列出孟德尔四条假说
第三步  演绎推理·作出预测   ──  弹窗 + 顶部指令卡：预测测交后代 1∶1
第四步  实验验证·得出结论   ──  ★ 本模拟的全部 9 步流程 ★
                                 亲手做实验 → 自己数结果 → 与 1∶1 比较 → 作答
```

**设计意图**：模拟器的"戏份"集中在第四步。前三步用弹窗一次性交代（5 秒可读完），把 90% 的交互预算花在"亲手做 + 亲手数"上。

### 2.4 遗传学数学约束（为什么是 48 / 16 / 3）

这是一个**必须自洽**的数值系统，四个条件同时约束：

| # | 约束 | 数学表达 |
|---|------|----------|
| 1 | 正常条件下要能**精确**得到 1∶1 | 总数必须能被 2 整除 |
| 2 | 异常条件下要能**精确**得到 2∶1 | 总数必须能被 3 整除 |
| 3 | 3 个豆荚装的种子数要**相等** | 总数必须能被 3（豆荚数）整除 |
| 4 | 每穴播 3 粒，田地要**刚好播满** | 总数 = 16 × 3 |

求解：`总数 ∈ 2ℤ ∩ 3ℤ ∩ 3ℤ`，且 `总数 = 48`（由 16 穴 × 3 粒确定）。

- `48 / 2 = 24` → 正常条件：**24 ∶ 24**，分离比 `1 : 1` ✅
- `48 × 2/3 = 32` → 异常条件：**32 ∶ 16**，分离比 `2 : 1` ✅
- `48 / 3 = 16` → 每个豆荚 **16 粒** ✅
- `48 / 16 = 3` → 每穴 **3 粒** ✅

**结论：48 是同时满足全部四项约束的最小可行配置之一，且它同时被 2、3、16 整除，没有任何"凑数"痕迹。** 这也是"3 个豆荚 → 48 粒 → 16 穴 × 3 粒"这条链路能够自然闭合的原因。

> ⚠️ 若未来要改穴数或每穴粒数，必须重新解这个联立约束，不能只改单点。

代码位置：`prepareSeeds()`（第 2469 行）

```js
// 48 粒子代的基因型：正常 → 24 高 : 24 矮（1:1）；含 a 雄配子半致死 → 32 高 : 16 矮（2:1）
const tall = S.cond === 'normal' ? TOTAL_PLANTS / 2 : TOTAL_PLANTS * 2 / 3;
```

### 2.5 教学风险点与规避方案

| 风险 | 现象 | 规避设计 |
|------|------|----------|
| **R1 颜色替代观察** | 高茎画绿、矮茎画橙 → 学生"看颜色识图"，不需要比较高度 | 《配色原则》写进代码注释：`PLANT_C` 统一色板，`pheno` **只影响形态不影响颜色**；`.cell.mature` 统一中性描边；删除 `.tag` 格位名牌 |
| **R2 程序替学生数** | 每格名牌直接写"高 2 矮 1" | 名牌整体删除，只保留中性格位编号 1–16 |
| **R3 去雄表征错误** | 去雄后只剩虚线圈 → 学生以为整朵花被掏空，也不理解"为什么还要授粉" | `svgBloom()` 的 `emas` 分支**加回雌蕊**（柱头 + 花柱 + 虚线圈） |
| **R4 一键完成** | "一键套袋"让"3 朵花套 3 次"的机械重复感消失 | 逐朵状态位 `flowers[i].bag`，必须点 3 次 |
| **R5 结论剧透** | 地块按表型着色、光环提示 | 移除全部按表型着色的地块样式 |
| **R6 数不清** | 48 株散在 16 格 + 2.5D 投影，肉眼看不清也数不准 | 「分类展示」把 48 株拔出来搬到同一平面并排摆放，计数才变得可完成 |

> **关于"颜色"的边界（重要）**：去色只针对**需要学生观察的材料**（田间植株、地块）。**观察完成之后的结论面板**（株数卡、饼图、对比条）仍使用绿/橙双色——这是**数据图例**，与教材的结果统计图一致，不构成观察捷径。这条边界是本项目的显式设计决策，不是遗漏。

### 4.1 第 1 步 · 去雄

- **教学目标**：理解豌豆闭花受粉 → 必须在花蕾期去雄；去雄是"切掉雄蕊"，不是"切掉花"
- **交互**：解剖刀横向划过花蕾，出现**切割线 + 刀锋 emoji（🔪）**，划过即完成该朵
- **状态**：`S.flowers[i].emas = true`
- **反馈**：Toast「✓ 3 朵花全部去雄」（同类进度复用同一条气泡）
- **验收**：划过 3 朵才 `advance(2)`；未划完仍停在第 1 步；切割动画元素必须是刀，不是手指
- **教学细节**：去雄后的花朵**保留雌蕊**（柱头 + 花柱 + 虚线圈）——这才是去雄的真实结果，也是接下来授粉的作用部位

### 4.2 第 2 步 · 套袋（逐朵）

- **教学目标**：隔离外来花粉；体会"一朵一朵来"的实验操作感
- **交互**：把纸袋**拖到某一朵花上**，袋子**真实罩住这朵花**（`<div class="cover">` 覆盖层，宽度 ≈ 花头 ×1.34、高度 ×1.54，带袋口捆扎带与虚线褶线）
- **状态**：`S.flowers[i].bag = true`；`S.bagged` 为**派生量**（3 朵是否全套）
- **验收**：套 1 朵仍停第 2 步；套满 3 朵才 `advance(3)`；`.cover` 覆盖面积必须 ≥ 花头
- **关键实现**：`bagged` 降级为派生量（`syncBagged()`），使"3 朵花套 3 次"成为天然结果而非特判

### 4.3 第 3 步 · 取粉

- **交互**：把毛笔拖到父本成熟花药（`#anthers`）上
- **状态**：`S.pollen = 100`
- **验收**：花粉值到达 100 才 `advance(4)`

### 4.4 第 4 步 · 授粉（揭袋 + 涂抹）

- **教学目标**：授粉是"把花粉涂到雌蕊柱头上"，作用部位是雌蕊（呼应 4.1 保留雌蕊的设计）
- **交互（两段，顺序不可颠倒）**：
  1. **揭袋**：按住 `.cover.liftable` **向上滑动** → 袋子提起消失（`doDeflower(i)`，`f.bag = false`）
  2. **授粉**：用带粉毛笔**横向划过**花朵（`strokeStart(e,'smear',i,el)` → `actFert(i)`）
- **验收**：3 个袋全部揭下后**仍停在第 4 步**；3 朵全部授粉才 `advance(5)`；任一环节漏做都不能推进

### 4.5 第 5 步 · 再套袋

- 与第 2 步同一交互，但**文案与后续分支不同**（`firstTime = (S.step === 2)` 判定）
- 完成后 `advance(6)` 并提示「人工授粉完成，接下来等待结种子」

### 4.6 第 6 步 · 收种子（新增环节）

- **教学目标**：授粉 ≠ 立刻有种子，中间必须有**子房发育成豆荚**的过程
- **交互**：花头（`.bhead`）在 `S.step >= 6` 时**整体切换为豆荚模式**（`.bhead.podmode`）；豆荚**自身是拖拽源**，直接拖进种子盆 `[data-drop="seedpot"]`（**不走"先选中工具再拖"的流程**）
- **视觉**：豆荚为**细长弯月形**（`viewBox="0 0 30 76"`，路径 `M16 6 C5 20, 3 48, 13 70 C22 60, 24 28, 16 6 Z`）+ 内壁 4 个种子鼓包；可拖拽提示为**整颗豆荚呼吸 + 绿色光晕**（`.cando { animation:podBreath; filter:drop-shadow(...) }`）
- **数量自洽**：3 个豆荚 × 16 粒 = 48 粒，正好够 16 穴 × 3 粒
- **验收**：`S.step >= 6` 时顶端必须是 `.bhead.podmode` 而非花；3 个豆荚全部采收才 `advance(7)`

> **设计迭代记录**：豆荚初版画成左右完全对称的柳叶形，被一眼看成"叶片"；且 🌰 emoji 提示叠在豆荚底部像一坨土。最终改为弯月形 + 内壁鼓包 + 去掉 emoji，改用"呼吸光晕"表达可拖拽。

### 4.7 第 7 步 · 播种

- **交互**：把种子拖进田地格位（`[data-drop="cell"]`），每穴 3 粒；提供「⚡ 一键播满」加速按钮
- **状态**：`S.cells[i] = { stage, geno:[3 个基因型] }`；`S.seedIdx` 计已播穴数
- **动画**：只为**刚播种的那一格**播放破土动画（`sproutAnim(i)`），避免整块地重播
- **验收**：16 穴播满后 `advance(8)`；`#field .pl` 数量 = 48

### 4.8 第 8 步 · 生长观察

- **交互**：点「🌱 让它们生长」（`#btnGrow`）→ 逐格错峰长成（`growAll()`，每格一个 `setTimeout`）
- **验收**：48 株全部长成；未成熟时**不应存在任何高矮标签**（`document.querySelectorAll('.tag').length === 0`）

### 4.9 第 9 步 · 分类统计（新增功能）

- **教学目标**：把"观察—计数"这个认知环节交还给学生
- **入口**：`#btnSort`（`🔍 分类展示`），仅在 `tally().n === 48 && S.step >= 8` 时出现
- **三段链路**：
  1. **拔苗**：48 株按 9ms 步长依次加 `.plucking`，播放 `pluckOut`（上抬 34px + 缩至 0.42 + 淡出）
  2. **飞行（FLIP）**：`harvestFieldRects()` 采集每株的**真实屏幕位置** → 分类格渲染完成后，用 `getBoundingClientRect()` 实测目标位置，以 `translate + scale` 从田间位置飞到分类格
  3. **分堆 + 计数**：左右两列（高茎 / 矮茎），下方 `.sortfoot` 显示「高茎 24 株 / 矮茎 24 株 / 比例 1 : 1」
- **"同一把尺子"原则**：两堆共用同一 `.ps` 容器高度，`svgSprig(pheno)` 用同一 `viewBox`、同底边对齐 → 矮茎是**真的矮**，不是"缩小画"
- **可逆**：按钮变为「↩ 还原田地」，点击回到田地视图
- **验收**：左右各 24；统计条含「高茎 24」「矮茎 24」「1 : 1」；两列 `.ps svg` 等高；可还原

> **FLIP 为什么必须用 `getBoundingClientRect()` 实测**：终点位于 2.5D 投影平面内、起点在外层 `--fs` 缩放的舞台上，两处坐标系不同。用实测矩形反推 `dx/dy/scale`，可以**自动吸收**投影变换与缩放，无需手算矩阵。

### 4.12 双条件对照（异常条件）

- 顶栏 `[data-cond]` 切换：`正常条件` / `异常条件 ❓`
- 异常条件隐藏设定：**父本 F₁（Aa）产生的含 a 的花粉（雄配子）有 50% 死亡**
- 推理链：父本有效花粉 `A ∶ a = 1 ∶ 0.5 = 2 ∶ 1`，母本（aa）只提供 a → 子代 `Aa ∶ aa = 2 ∶ 1` → **高茎∶矮茎 = 2∶1**
- 揭晓后叠加"修正假说后的预期参考线"，两轮数据入库后可对比
- **关键区分（必须讲清）**：① 致死的是**雄配子**且是**含 a 的那一类**；② 致死改变的是配子的**比例**，不是**种类**；③ **分离定律依然成立**，只是需要补充额外条件 → 这属于对假说的**修正**，不是**否定**

## 6. 交互设计方案

### 6.1 手势词汇表（尽量少，但每个都不同）

| 手势 | 语义 | 用在哪 | 为什么不用别的 |
|------|------|--------|----------------|
| **横向滑动** | 切割 / 涂抹 | 去雄（刀）、授粉（毛笔） | 两个动作都是"从一头到另一头"，横划是唯一有"行程"的手势 |
| **拖拽** | 把一个物件搬到另一个位置 | 套袋、取粉、播种、采收豆荚 | 与"位移"语义一一对应 |
| **向上滑动** | 揭下 | 揭纸袋 | "上提"是唯一能表达"拿掉罩子"的方向 |
| **点击** | 触发一个阶段的推进 | 生长、分类展示 | 非操作类动作，用按钮 |

> 同一手势在不同步骤下绑定不同语义（横划 = 切割 或 涂抹），靠**工具图标 + 切割线颜色 + 手指动画**三重提示区分。

### 6.2 三条输入通道

| 通道 | 说明 | 例 |
|------|------|-----|
| **A. 工具 → 目标** | 从工具架拖出工具，落到目标元素 | 纸袋 → 花；毛笔 → 花 |
| **B. 直接操作作物** | 作物自身是交互源，不需要先选工具 | 横划花蕾（自动选刀）；拖豆荚进种子盆 |
| **C. 按钮** | 阶段推进 / 加速 | 一键播满、让它们生长、分类展示 |

**通道 B 的设计理由**：真实实验里"刀在手上、花在眼前"，选工具是多余的一步。凡是**目标本身就能表达动作**的场景（切割一朵花、摘一颗豆荚），都走 B，减少一次点击。

### 6.3 反馈体系

| 反馈 | 触发 | 设计 |
|------|------|------|
| **Toast 气泡** | 每次有效操作 | `toast(msg, kind, key)` —— 第 3 参数 `key` 是"同类进度"标识；连续做同一件事（套第 1/2/3 朵）**复用同一条气泡就地更新文字**，避免 3 条叠在田地上方 |
| **进度芯片** | 状态变更 | `① 去雄 2/3` 逐项计数，学生一眼知道还差几朵 |
| **锁定提示** | 点了不该点的 | `blockedMsg(k)` 告诉学生"现在该做什么"而不是单纯 "禁止" |
| **可放置提示** | 拖拽开始 | `markDroppable()` 给合法落点加绿色描边 + 呼吸光晕 |
| **呼吸光晕** | 可拖拽的作物 | 豆荚 `podBreath` 整颗轻微缩放，**不叠 emoji**（emoji 叠在图形上会显出"贴纸感"） |
| **手指动画** | 全程 | `#handHint` 按当前动作切换图标 |
| **数字弹跳** | 统计刷新 | `numPop` 让新数字被注意到 |

### 6.4 视觉语言

| 维度 | 规则 |
|------|------|
| **主色** | `--brand:#2E7D5B`（豌豆绿）；高亮 `--accent:#F0A020`；警示 `--warn:#E5484D` |
| **植株配色** | **高矮一律同一绿色**（`stem:#3E9C5F` / `leaf:#5FBE85` / `pod:#7FC494` / `podD:#5FA878`） |

## 7. 技术方案

### 7.1 总体架构

单文件三段式，无构建、无框架：

| 段 | 行数 | 字节 | 内容 |
|----|------|------|------|
| `<style>` | 840 | 43,490 | 455 条 CSS 规则，全部内联 |
| HTML | 214 | 8,277 | 骨架 + 引导弹窗 |
| `<script>` | 1,702 | 66,409 | 84 个函数，纯 ES5+ 语法，无依赖 |
| **合计** | **2,767** | **137,278 B** | |

**图形 100% 程序化生成**：全部植物、花朵、豆荚、土壤、纸袋都由 JS 拼 `<svg>` 字符串产出（`svgPlant` / `svgSprig` / `svgBloom` / `svgStem` / `svgPod`），**没有任何图片文件**，也没有 base64 内联图。这不仅满足"零依赖"，也让形态可以按基因型参数化。

### 7.2 状态机与数据模型

```js
let S = null;
function freshState(cond){
  return {
    cond: cond || 'normal',
    revealed: false,
    step: 1,                       // 1..STEP_N（9）
    /* 每朵花独立的状态位：去雄 / 套袋 / 授粉。
       套袋与揭袋都按「朵」进行 —— 3 朵花就得套 3 次、揭 3 次。 */
    flowers: Array.from({length:FLOWER_N}, () => ({ emas:false, bag:false, fert:false })),
    bagged: false,                 // 派生：3 朵是否都已套袋
    podTaken: [false,false,false], // 3 个豆荚是否已摘走取种
    pollen: 0,                     // 0 | 100
    cells: Array.from({length:TOTAL_CELLS}, () => ({ stage:0, geno:[null,null,null] })),
    seedPool: [],                  // 本轮 48 粒的基因型（打乱）
    seedIdx: 0,                    // 已播穴数
    grown: false,
    sortOpen: false,
    roundRecorded: false,
    rounds: S ? S.rounds : [],     // 跨轮保留
    /* ... */
  };
}
```

**设计要点 1：逐朵状态位 + 派生量**

```js
function syncBagged(){ S.bagged = S.flowers.every(f => f.bag); return S.bagged; }
function bagCount(){ return S.flowers.filter(f => f.bag).length; }
const podCount = () => S.podTaken.filter(Boolean).length;
```

`bagged` 从"独立状态"降级为"派生量"，是"3 朵花套 3 次"能自然成立的关键：**没有任何一行代码专门处理"这是第 3 朵"**，`every()` 到第 3 次自然为真。同理 `podCount()`。

**设计要点 2：`cells[].stage` 三态**

| stage | 含义 | 渲染 |
|-------|------|------|
| 0 | 空穴 | `.hole` 脉冲 |
| 1 | 已播种（种子）| `svgPlant(pheno,'seed')` |
| 2 | 出苗 | `svgPlant(pheno,'sprout')` |
| 3 | 成熟 | `svgPlant(pheno,'mature')` + `.cell.mature` 中性描边 |

`tally()` 只统计 `stage === 3`，保证"没长成的植株不进球数"：

```js
function tally(){
  let tall = 0, dwarf = 0, sown = 0;
  S.cells.forEach(function(c){
    if (c.stage > 0) sown += SEEDS_PER_CELL;
    if (c.stage === 3) c.geno.forEach(function(g){ g === 'Aa' ? tall++ : dwarf++; });
  });
  return { tall: tall, dwarf: dwarf, n: tall + dwarf, sown: sown };
}
```

**补充：纸袋几何约束（踩坑记录）** —— 纸袋高 `1.54 × --bh`、`bottom:-7px`，于是**袋顶高出花头顶** `0.54 × --bh − 7` px；再叠加 `.bhead` 自身的 `top:1px`，得

```
所需 padding-top  ≥  0.54 × --bh − 6
```

| `--bh` | 所需 | 实取 | 实测袋顶距 `.bloom` 顶 |
|--------|------|------|------------------------|
| 52px（`body.ops` 默认） | 22.1 | **21px** | 1.92px 余量 ✅ |
| 45px（窄屏档） | 18.3 | **19px** | 3.70px 余量 ✅ |
| 41px（窄屏档） | 16.1 | **17px** | 0.86px 余量 ✅ |

> `.bloom` 与 `.pcard` 都是 `overflow:visible`，所以**不会真的被裁切**；该约束的作用是让纸袋不要压到卡片边框线上，保证"罩住花"的观感干净。三档均已实测有余量。

**设计要点 3：步骤推进唯一入口**

```js
function advance(to){
  if (to <= S.step) return;              // 幂等：重复触发不倒退
  const was = S.step;
  S.step = Math.min(STEP_N, to);
  if (was < 7 && S.step >= 7) prepareSeeds();   // 进入播种步才生成 48 粒基因型
  S.selectedTool = null;
  renderAll();
}
```

`advance()` 是幂等的——任何动作即使被连点多次也不会跳步或倒退。

### 7.3 渲染管线

```
状态变更 → renderAll()
             ├── renderField()     田地 16 格（含 fitField 自适应）
             ├── renderParents()   花枝 / 花 / 豆荚 / 纸袋
             ├── renderTools()     工具架启用态
             ├── renderCue()       顶部指令卡
             ├── renderStats()     结果统计
             ├── renderConcl()     结论 + 练习
             ├── renderSort()      分类展示区
             └── updateGuide()     引导提示
```

**全量重渲染 + 声明式拼字符串**：48 株 + 16 格的规模下，`innerHTML` 整体重建的耗时远低于做差异更新的复杂度成本。唯一的例外是**动画类操作**（`plucking`、`taken`、`grow`）——这些走 `classList.add` 直接改 DOM，避免重渲染把动画class洗掉。

### 7.4 2.5D 等距投影

**基础变换**（`.field`）：

```css
.field{
  --tile:112px;--gap:10px;
  display:grid;
  grid-template-columns:repeat(4,var(--tile));
  grid-template-rows:repeat(4,var(--tile));
  gap:var(--gap);
  transform:rotateX(var(--iso-x)) rotateZ(45deg);   /* --iso-x: 56deg */
  transform-style:preserve-3d;
}
```

- **无 `perspective`** → 纯轴测（正交）投影，天然等距，**且可安全做整体缩放**（有透视时缩放会改变透视关系）
- `rotateZ(45deg)` 把方形网格转成菱形，`rotateX(56deg)` 压扁成等距视角
- 视觉尺寸：`gw = 4×112 + 3×10 = 478px`，菱形对角线 `dia = 478×√2 ≈ 676px`

**立牌（billboard）—— 本项目的核心坑点**

植物必须始终直立面向观众，所以要用反向旋转抵消：

```css
.plw{position:absolute;width:0;height:0;
     transform:rotateZ(-45deg) rotateX(var(--iso-xn)) translateZ(26px)}  /* --iso-xn: -56deg */
```

**为什么必须加 `translateZ(26px)`（推导过程）**：

1. 立牌是"屏幕平行面"，地块是倾斜面，两者在屏幕上相交；
2. 立牌上任一点的屏幕深度**恒等于**它"落点"的深度（偏移算出恰为 0）→ 与自家地块**完全等深度**，BSP 排序不确定 → 植株会被土壤盖住 → **整片田看不见苗**；
3. 更隐蔽的是：即使做"零屏幕位移的法线前推"也不够。立牌越低（屏幕 Y 越大），它背后那块地表越靠近镜头。地表深度差 = `1.483 × 屏幕下移量`（系数来自 M_field 的逆变换：屏幕 (X,Y) 对应田地局部 `(0.707X ± 1.266Y)`，深度取 `0.586·(Δx+Δy)`）；
4. 所以前推量要盖过「立牌最低点背后的地表深度差」。本处最低点 ≈ 落点本身，落点的屏幕下移最多 ≈7px（`PLANT_POS` 的第三个落点）→ 需要 > 10.5，**取 26 留足余量**；
5. 上限是相邻格的深度差 **71.5**（田地局部单位），26 远小于它，**不会穿到前排地块之上**。

**每穴 3 株的落点**：

```js
const PLANT_POS = [[17,65],[41,49],[65,33]];   // 格子内百分比坐标
```

三条约束同时满足：
- ① 沿 "grid 对角线 (1,-1)" 方向排布 → 投影后正好是一条水平线、屏幕间距均匀（≈32px）
- ② 再加一点 (1,1) 方向的递进，让三株一前一后错落，像真实的一窝苗（**DOM 顺序即由远及近**）
- ③ 整体沿 (-1,-1) 方向再推 10px 局部单位 ≈ 屏幕上抬 8px，让植株的"基部"落在前排地块上沿之上。否则基部会被前排地块盖掉几像素，**茎看起来是断的**（立牌平面与前排地块面互相穿插，浏览器按整块多边形排序，做不到逐像素正确）

### 7.5 共面标签

格位编号（`.idx`）需要"随地块倾斜"又"文字正立"。若做成立牌，又会遇到 7.4 的深度问题；若直接 `rotateZ(45deg)`，文字会被压扁。

**解法**：`rotateZ(-45deg) scaleY(1/cos56°)`

```css
.idxw{position:absolute;left:15%;top:15%}
.cell .idx{
  position:absolute;left:0;top:0;
  transform:translate(-50%,-50%) rotateZ(-45deg) scaleY(1.788);
  font-size:9.5px;font-weight:800;color:rgba(255,255,255,.92);
  background:rgba(58,38,18,.42);padding:0 5px;border-radius:var(--rf);
}
```

`1.788 = 1/cos(56°)`。`rotateZ(-45deg)` + `scaleY(1/cos56°)` 的合成映射恰为恒等变换 —— **屏幕上是正立、不压缩的文字**，同时它仍是"画在地块平面内"的元素，深度天然正确，**不需要任何 translateZ**。

> ⚠️ **`scaleY` 的倒数与 `--iso-x` 绑定**：改 `--iso-x` 必须同步改 `1.788`。

### 7.6 自适应缩放 `fitField()`

```js
const ISO_COS = Math.cos(56 * Math.PI / 180);

function fitField(){
  const cw = elFieldStage.clientWidth, ch = elFieldStage.clientHeight;
  if (cw < 60 || ch < 60) return;
  const gw = (elField && elField.offsetWidth) || 478;
  const dia = gw * Math.SQRT2;                                     // 菱形对角线
  const W = dia + 24;                                              // 视觉宽
  const H = dia * ISO_COS + 34;                                    // 视觉高（含顶端植株抬头）
  const fs = Math.max(0.22, Math.min(1.3, Math.min(cw / W, ch / H)));
  elFieldZoom.style.setProperty('--fs', fs.toFixed(3));
}
```

- 舞台用**绝对定位 + `translate(-50%,-50%)` 居中**，内容比容器大时也不会被挤出裁掉
- `padding:46px 34px 20px`：上内边距 > 下内边距，因为投影后内容整体偏上（顶端植株要抬头 66−44 ≈ 22px），这样盒子中心才与内容中心重合。该值同时被 `fitField` 读取参与缩放计算
- 实测结果：1440×900 下 `--fs ≈ 1.53`（界面整体放大，远距离可读）；1280×720 下 `--fs ≈ 1.0`

### 7.7 FLIP 拔苗动画（跨坐标系飞行）

**问题**：起点是 `.pl`（3D 变换内 + 外层 `--fs` 缩放），终点是 `.sortwrap` 里的 `.ps`（另一个容器）。两者坐标系不同，手算矩阵极易出错。

**解法：起止两端都用 `getBoundingClientRect()` 实测屏幕位置，反推位移与缩放。**

```js
function harvestFieldRects(){
  const map = {};
  elField.querySelectorAll('.pl').forEach(function(pl){
    const r = pl.getBoundingClientRect();
    map[pl.dataset.i + '-' + pl.dataset.n] = {
      x: r.left + r.width/2, y: r.top + r.height/2, h: r.height
    };
  });
  return map;
}

function flyFromField(src){
  Array.from(elSortWrap.querySelectorAll('.ps')).forEach(function(el, k){
    const s = src[el.dataset.key];
    const r = el.getBoundingClientRect();
    const dx = s.x - (r.left + r.width/2), dy = s.y - (r.top + r.height/2);
    const sc = Math.max(0.12, Math.min(2.4, s.h / r.height));
    el.style.transformOrigin = '50% 100%';        // 以底部（根部）为缩放锚点
    el.style.transform = 'translate(' + dx + 'px,' + dy + 'px) scale(' + sc + ')';
    /* rAF + stagger 后归位到 transform:none */
  });
}
```

**优势**：
- 自动吸收 2.5D 投影、`--fs` 缩放、窗口尺寸变化——**不需要知道任何变换矩阵**
- `transformOrigin: 50% 100%` 让植株以根部为锚点缩放，符合"从土里拔出来"的物理直觉
- `scale` 上下限 `[0.12, 2.4]` 防止极端视口下的视觉炸裂

**拔苗时序**：

```
点击「分类展示」
  → harvestFieldRects() 采集 48 株屏幕位置
  → 48 株按 9ms 步长依次加 .plucking（pluckOut: 上抬 34px + 缩至 0.42 + 淡出）
  → 400ms 后：S.sortOpen = true; renderSort()（分类格 DOM 就位）
  → flyFromField(src)：每株从田间位置飞到分类格（rAF + stagger）
```

### 7.8 手势系统

**统一用 Pointer Events**（鼠标 / 触屏 / 触控笔一套代码）：

```js
function onToolDown(e){
  const k = e.currentTarget.dataset.tool;
  if (!toolEnabled(k)){ toast(blockedMsg(k), 'bad'); return; }
  e.preventDefault();
  drag = { tool:k, x0:e.clientX, y0:e.clientY, moved:false, el:null };
  document.addEventListener('pointermove', onPointerMove);
  document.addEventListener('pointerup', onPointerUp);
  document.addEventListener('pointercancel', onPointerUp);
}
```

**拖动阈值**：位移 > 8px 才认定为拖拽（`drag.moved = true`），并生成跟随光标的鬼影元素 `.ghost-el`。

**Ghost-click 过滤**（关键鲁棒性设计）：

```js
function isGhostClick(e){
  return (Date.now() - dragEnd.t < 400)
      && Math.abs(e.clientX - dragEnd.x) < 12
      && Math.abs(e.clientY - dragEnd.y) < 12;
}
```

手势结束后浏览器会**补发一次 `click`**（触屏尤其明显）。若不拦截，会出现"拖完袋子又触发一次点击"的重复操作。此处用「时间 < 400ms + 位移 < 12px」三重判定吞掉鬼影点击。

**指针捕获**：`el.setPointerCapture(e.pointerId)`（`try/catch` 包裹），确保手指滑出元素后仍能收到 `pointermove`。

**落点判定**：

```js
function accepts(tool, drop){
  if (tool === 'pod')   return drop === 'seedpot';
  if (tool === 'knife') return drop === 'mflower';
  if (tool === 'bag')   return drop === 'mflower';   // 落点是「某一朵花」，不是整株
  if (tool === 'brush') return drop === 'fflower' || drop === 'mflower';
  if (tool === 'seed')  return drop === 'cell';
  return false;
}
```

落点从 `mplant`（整株）改为 `mflower`（某一朵）是"逐朵套袋"的实现基础。

## 附录 C · 设计原则备忘（本次改造确立）

1. **不替学生得结论**：程序只提供材料与工具，观察与推理必须由学生完成。任何"用颜色 / 文字 / 高亮提前透露表型"的元素都必须移除。
2. **操作的颗粒度 = 真实的颗粒度**：3 朵花就套 3 次袋，不提供"一键套整株"。**逐朵状态位**是实现这种颗粒度的正确抽象；"3 朵全套完"应作为**派生量**而不是独立状态。
3. **手势要能自解释**：切割 = 横向滑动、罩住 = 拖拽、揭下 = 上滑。手势与物理动作一一对应时，学生不看说明书也会用。
4. **跨坐标系动画实测两端**：只要起点和终点位于不同的变换上下文，就用 `getBoundingClientRect()` 实测，不要手算矩阵。
5. **视觉反馈不能叠**：同类连续动作（套第 1/2/3 朵）必须复用同一条气泡，否则提示会糊满屏幕。
6. **比例要诚实**：分类展示时两堆必须用"同一把尺子"（同 viewBox、同底边），矮茎是真的矮，不是缩小画。
